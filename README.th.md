## ทำไมต้องมี

โมเดลเก่งราคาแพง ส่วน worker ถูกแต่พลาดได้ สกิลนี้ให้โมเดลเก่งทำหน้าที่ **ผู้ประสานงาน**
คือเข้าใจโจทย์ แตกเป็นตั๋วเล็ก ให้ worker ราคาถูกลงมือพิมพ์ และไม่เชื่อผลใดจนกว่าจะรันเทสซ้ำเอง

## ลำดับการทำงาน

| ขั้น | ทำอะไร |
|---|---|
| **เช็กก่อนเริ่ม** | `scripts/preflight.sh` ตรวจว่าสกิลที่ต้องใช้ติดตั้งครบไหม ถ้าขาดจะพิมพ์คำสั่ง `npx skills add` ให้ |
| **ซักให้เคลียร์** | โจทย์ไม่ชัด ให้สัมภาษณ์ก่อน (`grill-with-docs`) จะได้ไม่แตกตั๋วจากการเดา |
| **สเปก → ตั๋ว** | `to-spec` แล้ว `to-tickets`: ตั๋วละหนึ่งจุดประสงค์ ระบุไฟล์ มีเทสของตัวเอง บอกว่าตั๋วไหนรอตั๋วไหน |
| **แจกงาน** | CLI ฟรีหรือราคาถูกก่อน โมเดลระดับกลางถัดมา โมเดลแรงสุดเฉพาะงานออกแบบและบั๊กยาก |
| **ตรวจเอง** | ดูว่าไฟล์เปลี่ยนจริง รัน build กับเทสซ้ำ เช็กว่าเทสพังได้จริงเมื่อโค้ดผิด รายงานของ worker คือคำกล่าวอ้าง ไม่ใช่ผลลัพธ์ |
| **รีวิวอิสระ** | โมเดลคนละตัวกับคนเขียนรีวิว diff เทียบกับสเปก |
| **ส่งต่อ** | `handoff` ทิ้งสถานะ คำถามที่ค้าง และตั๋วถัดไปให้ session ต่อไป |

## ติดตั้ง

```bash
npx skills add ptsuriya/dispatch-workers-skill
```

เพิ่ม `-g` เพื่อติดตั้งระดับผู้ใช้ จากนั้นสั่ง agent ให้แจกงาน หรือเรียกสกิลตามชื่อ

## ต้องมีอะไรบ้าง

รัน preflight ได้ทุกเมื่อ:

```bash
bash scripts/preflight.sh
```

| ประเภท | รายการ | ถ้าขาด |
|---|---|---|
| **สกิลที่ต้องมี** | `caveman` `ponytail` `grilling` `domain-modeling` `grill-with-docs` `to-spec` `to-tickets` `handoff` `code-review` | หยุด และพิมพ์คำสั่ง `npx skills add` |
| **สกิลเสริม** | `wayfinder` `implement` `diagnosing-bugs` `tdd` | แสดงว่าไม่มี แต่ทำงานต่อได้ |
| **CLI ของ worker** | `muse` `codex` `copilot` `opencode` (มีแค่บางตัวก็ได้) | ข้ามไปใช้ตัวถัดไป |

script จบด้วย `0` เมื่อสกิลที่ต้องมีครบ และ `1` เมื่อขาด

## โครงสร้าง repo

```
SKILL.md                  ตัวสกิล
scripts/preflight.sh      ตรวจสกิลที่ต้องพึ่ง
references/workers.md     วิธีเรียก CLI ของ worker และกับดัก (ผลว่าง, โควต้าหมด, stdin)
```

## ข้อจำกัดตามจริง

- คำสั่งเรียก CLI ใน `references/workers.md` เป็นรูปแบบทั่วไป flag เปลี่ยนตามเวอร์ชัน ให้รัน `--help` ก่อนครั้งแรก
- preflight เช็กแค่ว่ามีสกิลอยู่ในเครื่อง ไม่ได้เช็กว่าเป็นเวอร์ชันที่คุณคาดไว้
- สกิลให้กฎกับผู้ประสานงาน แต่บังคับ worker ไม่ได้ จึงมีขั้น "ตรวจเอง" เป็นขั้นที่สี่
